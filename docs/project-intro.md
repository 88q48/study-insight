## 三、完整简介（300 字左右）

学生手上有两样东西：一叠错题，一份屏幕使用时间。前者记录错了什么，
后者记录花了多少时间，但它们从来不放在一起看。结果是错题本越记越厚，
时间也没少花，却说不清问题到底出在哪。

学情洞察把这两条线拼起来。错题这边看科目分布、知识点薄弱榜和每日消化趋势；
专注这边把每天的学习时长和当天消灭的错题数画在同一张双轴图上，
柱子很高而折线很平的日子，会被直接指出来。

在此基础上生成「今日重做清单」：按每个知识点**还剩多少道没消化**排序，
告诉你今天先做哪几道、做几道。做完在手机上标记，清单下次就短一条。
全部掌握的知识点会自动退出清单，不会一直占着位置。

技术上，Windows 端通过 Win32 API 采集前台窗口与空闲状态，
FastAPI 负责数据接入与统计，看板有 Streamlit 和 ECharts 两套实现
（后者可直接挂在后端 `/dashboard` 路径下），
手机端用 React Native 完成错题录入、刷题练习和掌握标记。

## 五、推介时的说法（口头讲）

**「和普通错题本有什么区别」**

普通错题本只告诉你错了什么。这个系统还会告诉你：这一科的错误是不是
集中在某一类题上，你的时间是不是花在了不产生效果的地方，
以及今天晚上到底应该先做哪几道。

**「和屏幕时间监控有什么区别」**

屏幕时间只统计用了多久，不在乎你学了什么。我们把时长和当天的
错题消化量放在一起看，时长本身不是目标。

**「你的清单凭什么这么排」**

按每个知识点还剩多少道没消化排的。全部掌握的直接退出清单，
所以这张表每天做完都会变，不会一直挂着同样的名字。

## 六、当前完成度

| 模块 | 状态 | 说明 |
|---|---|---|
| 错题采集（Windows） | 已完成 | Win32 API 采集前台窗口与空闲状态 |
| 后端服务 | 已完成 | FastAPI + SQLite，11 字段正式契约 |
| 网页看板 | 已完成 | ECharts 版，支持页面内切换数据源与设备 |
| Streamlit 看板 | 已完成 | 双 Tab，与网页版数据一致 |
| 手机端 | 已完成 | React Native，录题 / 练习 / 统计 |
| 三端联调 | 已完成 | 手机录题 → 后端入库 → 看板刷新 |

### 支持的题型

选择题（A/B/C/D 四选项）与填空题，选择题可自动判对错。

### 主要接口

| 接口 | 用途 |
|---|---|
| `POST /api/v1/errors` | 录入错题 |
| `GET /api/v1/errors` | 查询错题列表 |
| `PATCH /api/v1/errors/{id}` | 更新掌握状态 |
| `DELETE /api/v1/errors/{id}` | 删除错题 |
| `GET /api/v1/errors/practice` | 按错题次数优先的练习队列 |
| `POST /api/v1/errors/{id}/attempts` | 记录一次做题结果 |
| `POST /api/v1/events/batch` | 批量上传应用使用记录 |
| `GET /api/v1/devices/{id}/analysis` | 看板分析数据（11 字段） |
| `GET /dashboard` | 看板静态页（可由后端直接提供） |
